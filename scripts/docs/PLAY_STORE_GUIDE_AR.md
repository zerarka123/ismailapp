# دليل نشر «مرسى» على Google Play

> آخر تحقق من متطلبات Google: 20 أكتوبر 2026. القواعد تتغير، فراجع صفحات Google المذكورة قبل الإرسال.

## 0) الصورة الكاملة (بالترتيب)

| # | المرحلة | أين | تقريبًا |
|---|---|---|---|
| 1 | تجهيز Supabase للجوال (رمز البريد + SMTP) | Supabase / Resend | ساعة |
| 2 | رفع نسخة الموقع المحدَّثة (صفحات الخصوصية والحذف) | GitHub ← Cloudflare | 15 د |
| 3 | تثبيت الأدوات وبناء ملف AAB الموقَّع | حاسوبك | 1–2 ساعة |
| 4 | تجربة التطبيق على هاتف حقيقي | هاتفك | ساعة |
| 5 | إنشاء حساب مطوّر Google Play (25$) | play.google.com/console | يوم–أيام (التحقق) |
| 6 | تعبئة صفحة المتجر + نماذج السياسة | Play Console | 2–3 ساعات |
| 7 | اختبار مغلق: 12 مختبرًا × 14 يومًا متواصلة | Play Console | 14 يومًا على الأقل |
| 8 | طلب الوصول للإنتاج ثم المراجعة | Play Console | أيام |

**تنبيه الوقت:** إن كان حسابك «شخصيًا» (Personal) فلن تستطيع النشر العام قبل اختبار مغلق بـ **12 مختبرًا على الأقل، كلٌّ منهم مشترك لآخر 14 يومًا متواصلة**، ثم تطلب الوصول للإنتاج. (كان الرقم 20 سابقًا؛ تحقق من الرقم الحالي داخل Play Console.) حسابات «المؤسسة» معفاة لكنها تحتاج توثيق نشاط تجاري. خطّط لنحو 3 أسابيع من اليوم الأول للنشر العام.

الجزائر **مدعومة** لتسجيل مطوّري Google Play حسب جدول Google الرسمي. الرسوم 25$ مرة واحدة وتحتاج بطاقة دفع دولية (CIB لا تعمل غالبًا؛ بطاقة Visa/Mastercard دولية أو بطاقة افتراضية من مزوّد موثوق).

## 1) تجهيز Supabase (ضروري، وإلا لن تصل رموز التأكيد)

التطبيق يستعمل **رمزًا من 6 أرقام** يصل بالبريد عند إنشاء الحساب ونسيان كلمة السر (لا روابط، لأن الروابط تفتح المتصفح لا التطبيق).

1. **SMTP مخصّص:** Authentication ← Emails ← SMTP Settings: Host `smtp.resend.com`، Port `465`، Username `resend`، Password = مفتاح API من Resend، Sender `noreply@marsadz.app`. لا يعمل إلا بعد أن يصير نطاق marsadz.app **Verified** في Resend. بدون هذا، يرسل Supabase للبريد المدمج فقط إلى أعضاء فريقك وبحد منخفض جدًا.
2. **قوالب الرسائل:** Authentication ← Emails ← Templates. في قالبي **Confirm sign up** و**Reset password** احذف زر الرابط `{{ .ConfirmationURL }}` واكتب:

```html
<h2>مرحبًا بك في مرسى</h2>
<p>رمز التحقق الخاص بك:</p>
<p style="font-size:28px;letter-spacing:6px;direction:ltr"><b>{{ .Token }}</b></p>
<p>الرمز صالح لمدة محدودة. إن لم تطلبه فتجاهل هذه الرسالة.</p>
```
3. Authentication ← Providers ← Email: أبقِ **Confirm email** مفعّلًا. طول الرمز الافتراضي 6 (التطبيق يقبل 6–10 أرقام).
4. Authentication ← URL Configuration: Site URL = `https://marsadz.app`.
5. نفّذ `migrations/002_condition_jetski.sql` في SQL Editor إن لم تنفّذه.
6. أنشئ حساب مراجعة Google (القسم 6-د).

## 2) رفع الموقع

ادفع المشروع إلى GitHub كالمعتاد. أمر البناء `npm run build` يولّد تلقائيًا الصفحات الثابتة `privacy.html` و`terms.html` و`delete-account.html` (يقرأها زاحف Google دون JavaScript). بعد النشر افتح **في نافذة خاصة**:

- `https://marsadz.app/privacy`
- `https://marsadz.app/delete-account`

اضغط «عرض المصدر» (view-source) وتأكد أن نص السياسة موجود فيه. إن ظهر هيكل فارغ فاستعمل بدلها `https://marsadz.app/privacy.html` و`/delete-account.html` في Play Console.

كذلك افتح التطبيق على الموقع بعد النشر وتأكد أن الصور والتسجيل يعملان: ملف `public/_headers` يضيف سياسة أمان (CSP) قد تمنع خطأً ما لم نتوقعه؛ إن حدث، أرسل لي رسالة الخطأ من وحدة التحكم.

## 3) بناء ملف AAB الموقَّع (Windows)

**الأدوات (مرة واحدة):**
- Node.js **22** LTS
- JDK **21** (Temurin)
- Android Studio **Otter 2025.2.1 أو أحدث** (Capacitor 8 يتطلبه). من SDK Manager ثبّت منصة **Android 16 (API 36)**.

**الأوامر** (داخل مجلد المشروع، ومعك ملف `.env` فيه مفتاحا Supabase):

```
npm install
npm run android:setup
```
هذا يبني الويب، وينشئ مجلد `android/`، ويولّد الأيقونات وشاشة البداية، ويضبط الإعدادات، ويطبع ملخصًا فيه **targetSdkVersion** (يجب أن يكون 36 أو أكثر) والصلاحيات (المتوقع: الإنترنت + الموقع). افتح مجلد `android` مرة واحدة في Android Studio ودعه يكمل Gradle Sync (ينشئ `local.properties`)، ثم أغلقه.

**مفتاح التوقيع (مرة واحدة):**
```
npm run keystore
```
يسألك عن كلمة سر (اختر طويلة) وبعض الأسماء. ينتج `keystore/marsa-upload.jks`.
- انسخه مع كلمة السر إلى **مكانين** (فلاشة + مدير كلمات سر).
- لا ترفعه إلى GitHub (مستثنى في `.gitignore`) ولا ترسله لأي أحد، ولا لي.
- هذا «مفتاح الرفع». عند أول رفع سيعرض Play Console **Play App Signing** فاقبله (الافتراضي): Google تحتفظ بمفتاح التوقيع النهائي، وإن ضاع مفتاح الرفع تستطيع طلب إعادة تعيينه.

**بناء النسخة:**
```
npm run android:release
```
يطلب كلمة سر المفتاح ثم ينتج `release/marsa-1.0.0-1.aab`. لكل تحديث لاحق: `npm run android:release -- --bump` (يرفع versionCode تلقائيًا؛ Google ترفض رقمًا مكرّرًا).

**معرّف التطبيق** `app.marsadz.marsa` (في `capacitor.config.json`) **لا يمكن تغييره بعد أول رفع**. غيّره الآن إن أردت اسمًا آخر، قبل `android:setup`.

## 4) تجربة على هاتف حقيقي (قبل الرفع)

ثبّت الـ AAB أو شغّل من Android Studio، وجرّب:
- تصفح كزائر ← لا يظهر أي رقم هاتف.
- إنشاء حساب ← يصل الرمز ← الدخول ← نسيان كلمة السر ← الرمز ← كلمة جديدة.
- نشر إعلان بصور من الكاميرا والمعرض.
- تسجيل نشاط ثم زر «حدّد موقع نشاطك» (يظهر طلب إذن الموقع).
- زر الرجوع في الهاتف (خصوصًا على Android 16) وإعادة فتح التطبيق دون إنترنت.
- حذف الحساب من «حسابي».
- شريط الحالة وأزرار النظام لا تغطي المحتوى (الحافة للحافة).

لم أستطع تشغيل Gradle ولا التوقيع (jarsigner) داخل بيئتي هنا؛ المنطق الذي يعدّل ملفات Android مُختبَر على قوالب مشابهة، لكن **أول بناء حقيقي على جهازك هو الاختبار الفعلي**. إن ظهر خطأ فأرسل لي نصّه كاملًا.

## 5) الحساب وصفحة المتجر

**حساب المطوّر:** play.google.com/console ← إنشاء حساب ← «شخصي» غالبًا. ستدفع 25$ وترفع هوية وتنتظر التحقق. اجعل **البريد العام** support@marsadz.app (يجب أن تنشئه فعليًا عبر Cloudflare Email Routing).

**إنشاء التطبيق:** الاسم من `store/listing-ar.txt`، اللغة الافتراضية العربية، النوع تطبيق، مجاني. التصنيف المقترح: **التسوق (Shopping)**.

**الأصول:**
- أيقونة 512×512: `store/icon-512.png`
- صورة الميزة 1024×500: `store/feature-graphic-1024x500.png`
- لقطات شاشة الهاتف (2 إلى 8): **صوّرها من التطبيق الحقيقي على هاتفك** ببيانات حقيقية. Google تمنع اللقطات المضلّلة، لذلك لم أولّدها لك من بيانات تجريبية.
- النصوص: `store/listing-ar.txt` (مفحوصة ضمن الحدود: 30 / 80 / 4000).

## 6) النماذج في Play Console (قسم «سياسة التطبيق»)

### أ) سياسة الخصوصية
الرابط: `https://marsadz.app/privacy`

### ب) حذف الحساب (Data safety ← Data deletion)
- «يستطيع المستخدم إنشاء حساب من داخل التطبيق»: **نعم**.
- رابط الحذف: `https://marsadz.app/delete-account`
- الحذف داخل التطبيق: «حسابي ← حذف حسابي نهائيًا».

### ج) Data safety (أمان البيانات)
أجب بما يطابق التطبيق فعلًا. الجدول التالي مبني على الكود الحالي:

| النوع | يُجمع؟ | إلزامي؟ | الغرض | يُشارك مع طرف ثالث؟ |
|---|---|---|---|---|
| Email address | نعم | نعم | وظائف التطبيق، إدارة الحساب | لا* |
| Name | نعم | نعم | وظائف التطبيق، إدارة الحساب | لا* |
| Phone number | نعم | اختياري | وظائف التطبيق (يراه المسجّلون فقط) | لا* |
| User IDs | نعم | نعم | إدارة الحساب | لا* |
| Photos | نعم | اختياري | وظائف التطبيق (صور الإعلانات) | لا* |
| Approximate + Precise location | نعم | **اختياري** (عند الضغط على زر الموقع) | وظائف التطبيق (موقع النشاط) | لا* |
| Other user-generated content | نعم | اختياري | وظائف التطبيق (نصوص الإعلانات، البلاغات، المفضلة) | لا* |

\* مزوّدو الخدمة (Supabase، Cloudflare، خدمة البريد) يعالجون البيانات **نيابةً عنك**؛ وفق تعريف Google لا يُحسب هذا «مشاركة». تحقّق من التعريف الحالي في نموذج Play Console قبل الاعتماد على هذا.

أجوبة ثابتة: البيانات **مشفّرة أثناء النقل: نعم** (HTTPS). **لا** تجمع: معلومات مالية، صحة، جهات اتصال، رسائل، ملفات، سجل تصفح، معرّفات الجهاز/الإعلانات، سجلات الأعطال. التطبيق لا يحتوي SDK للإعلانات أو التحليلات.

نقطة رمادية: خوادم الاستضافة قد تسجّل عنوان IP لأغراض الأمان. إن لم تكن متأكدًا فاقرأ تعريفات أنواع البيانات في النموذج وأجب بالأحوط.

### د) وصول التطبيق (App access)
بعض الأقسام تتطلب تسجيل الدخول، فاختر «بعض الوظائف مقيّدة» وقدّم حسابًا:
1. أنشئ حساب مراجعة ببريد تتحكم به وأكمل تأكيده بالرمز.
2. أضف إعلانًا واحدًا على الأقل ببيانات حقيقية ليرى المراجع محتوى.
3. اكتب في النموذج: البريد وكلمة السر، وملاحظة: «الدخول بكلمة السر لا يحتاج رمزًا».

### هـ) باقي الإقرارات
- الإعلانات: **لا يحتوي إعلانات**.
- الجمهور المستهدف: **18 سنة فأكثر** فقط (ليس للأطفال، فلا ينطبق برنامج العائلات).
- تصنيف المحتوى (IARC): لا عنف ولا محتوى جنسي ولا مخدرات ولا قمار؛ **المستخدمون يتفاعلون / محتوى من المستخدمين: نعم**؛ مشاركة الموقع مع مستخدمين آخرين: نعم (موقع النشاط الاختياري)؛ مشتريات رقمية: لا.
- تطبيق إخباري / حكومي / مالي / صحي / كوفيد: **لا**.
- معرّف الإعلانات: **لا يستخدمه**.
- المحتوى من المستخدمين (UGC): يوجد زر إبلاغ في كل إعلان ونشاط، وشروط تمنع المحتوى المخالف، وإدارة تراجع البلاغات.

### و) نسخة Google Play بلا مدفوعات
هذه النسخة لا تعرض أي سعر اشتراك ولا زر دفع ولا طريقة دفع خارجية، وهذا مقصود لتفادي مخالفة سياسة المدفوعات. **لا تضف** لاحقًا نصًا يوجّه المستخدم للدفع خارج التطبيق في هذه النسخة.

## 7) الاختبار المغلق ثم الإنتاج

1. Testing ← **Internal testing**: ارفع الـ AAB أولًا (دون مراجعة) لتتأكد أنه يثبَّت من متجر Google.
2. Testing ← **Closed testing**: أنشئ مسارًا، ارفع نفس الإصدار، أضف **12 بريد Gmail على الأقل** (أصدقاء، قرّاء، صيادون)، وأرسل لهم رابط الانضمام. اطلب منهم **ألا يغادروا الاختبار 14 يومًا متواصلة** وأن يجرّبوا التطبيق فعلًا وتكتب ملاحظاتهم. من ينسحب قبل 14 يومًا لا يُحتسب. جنّد 15–20 احتياطًا.
3. بعد 14 يومًا: Dashboard ← **Apply for production** وأجب عن الأسئلة بصدق (ماذا اختبرتم، ماذا أصلحتم).
4. بعد الموافقة: Production ← Create release ← ارفع الـ AAB ← أرسل للمراجعة.

- **الاحتفاظ بالمفتاح:** ضياع مفتاح الرفع وكلمته يعقّد التحديثات (يمكن طلب إعادة تعيينه من Google، لكنه يؤخرك).
